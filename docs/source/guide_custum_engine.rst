Custom Energy Engines
=====================

Use a custom energy engine when a Hamiltonian term is not covered by a
built-in ``System.add_*`` method. An engine is a functionally pure JAX function
that returns one scalar energy. OpenFerro JIT-compiles it by default and derives
the force as the negative gradient.

Engine signatures
-----------------

Field values are positional arguments and the parameter array is last:

.. code-block:: python

   def self_energy(field_values, parameters):
       ...

   def mutual_energy(field_1_values, field_2_values, parameters):
       ...

   def triple_energy(
       field_1_values, field_2_values, field_3_values, parameters
   ):
       ...

The returned value must be a scalar. Forces have the same shapes as the field
arrays and are generated by differentiating with respect to the field-value
arguments.

Register an engine
------------------

This onsite quartic term acts on one three-component field:

.. code-block:: python

   import jax.numpy as jnp

   import openferro as of


   lattice = of.SimpleCubic3D(4, 4, 4)
   system = of.System(lattice)
   local_mode = system.add_field("u", ftype="R3", value=0.0)


   def onsite_energy(u, parameters):
       k2, alpha = parameters
       u2 = jnp.sum(u**2, axis=-1)
       return jnp.sum(k2 * u2 + alpha * u2**2)


   onsite = system.add_self_interaction(
       "onsite",
       field_ID=local_mode.ID,
       energy_engine=onsite_energy,
       parameters=[1.0, 0.1],
   )

   energy = system.calc_total_potential_energy()
   system.update_force()

Use ``system.add_mutual_interaction`` or ``system.add_triple_interaction`` for
terms coupling two or three fields. Each interaction ID must be unique. The
returned interaction stores its parameters, which can be inspected or updated
without rebuilding the system:

.. code-block:: python

   onsite.set_parameters([0.8, 0.1])

JAX requirements
----------------

Inside an engine:

* use ``jax.numpy`` for calculations involving fields or parameters;
* do not mutate Python objects, perform file I/O, or log values;
* keep array shapes and parameter ordering explicit; and
* pass numerical data through arguments rather than capturing large arrays in
  a closure, especially when arrays may be sharded across devices.

Set ``enable_jit=False`` while debugging an engine if ordinary Python tracebacks
are more useful. Restore the default JIT behavior before measuring performance.
Validate a new term with an independent energy calculation, symmetry checks,
and finite-difference comparison of at least a few force components.

Explicit custom force registration is not a public 0.2 API. See
:doc:`feature_status` for the exact promoted scope and :doc:`quickstart` for a
complete minimal simulation.
